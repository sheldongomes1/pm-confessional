  Constraint: do NOT change the embedding model, the corpus embeddings, the
  pgvector index, or the audit pipeline. The 701 vectors are not the bottleneck.
  Cosine top-20 over 701 vectors is microseconds — keep that intact.

  Step 1 — Measure before you fix.
  Add server-side timing logs to POST /api/regrets/search that report ms for:
    a. query embedding call to Vertex (Gemini text-embedding-004)
    b. pgvector cosine top-20
    c. Gemini Flash rerank
    d. total handler time
  Log the four numbers per request to stdout AND return them in a debug header

  making any other change. We fix what's actually slow, not what we assume.

  Step 2 — Eliminate cold start.
  Replit free/dev instances sleep. Either flip this Repl to Reserved VM /
  "Always On", or add a self-ping endpoint /healthz that an external cron hits
  every 4 minutes to keep the instance warm. Document which one you chose.

  Step 3 — Make the rerank step optional / cheaper.
  With Gemini text-embedding-004 over 701 confessions, top-20 cosine is already
  strong. Two changes:
       cosine-ranked results directly. Add a server config flag RERANK_THRESHOLD
       so I can tune it.
    b. If we DO rerank, switch from Gemini Flash to Gemini Flash Lite, and rerank

  Step 4 — Add a query-embedding LRU cache.
  In-memory Map keyed by sha256(normalized_query), value = embedding vector.

  Step 5 — Kill the silent loading UX.
  On the search results page, the moment the user clicks Search Archive:
    - Render 5 skeleton cards immediately (animated shimmer, not a spinner)

  This is a perceived-latency fix, not a real-latency fix. Both matter.

  ---
  A few notes on why this prompt is shaped this way, in case you want to adjust:
  
  - It demands a measurement step first. Without timings you (and the agent) will guess. The four-number breakdown will show you whether it's cold start, rerank, or something neither of us suspects (DB
  connection pool, JSON parsing, network egress).
  - It explicitly forbids touching the corpus or index. Replit agents love to "improve" things that aren't broken. Lock those down.
  - The skeleton + counter UX is non-negotiable. Even after Steps 2–4, sometimes Gemini will be slow. The counter tells the user the system is alive and bounds their patience. This single change turns a "broken
  site" feel into a "powerful but careful AI" feel.
  - The 0.55 cosine threshold is a starting point, not a fixed value. Tune it based on quality. Most well-formed queries against 701 docs will easily hit 0.6+ on the top-1.

  If after Step 1 the agent reports back and the rerank is somehow not the bottleneck (rare), come back and we'll re-target. But 90% of "my LLM-backed search is slow" is rerank + cold start.
