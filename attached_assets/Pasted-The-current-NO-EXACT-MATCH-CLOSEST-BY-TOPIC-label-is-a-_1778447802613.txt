The current "NO EXACT MATCH — CLOSEST BY TOPIC" label is a passive warning that users glance past. People don't read; they scan. If you put 12 confession cards on the page, the brain
  reads "these answer my question" before the brain reads the small-caps disclaimer above them.

  The principle: if a user has to read a warning to interpret the result correctly, the result shouldn't be shown by default. Make it an active opt-in.

  Here's the prompt to paste into Replit's agent. It builds on the retrieval_confidence work from the last prompt, so make sure that's shipped first:

  Why this matters more than the cosine threshold change
  
  The threshold change (0.65 → 0.70) was a quality fix. This is a trust fix. They're different problems:

  - Quality: "the right answer is in there, but the system isn't surfacing it"
  - Trust: "the system signals confidence even when it has none"

  Trust failures cost more than quality failures because they're sticky. A user who gets a slightly off-topic top-1 once might shrug. A user who realizes the system was confidently giving them noise won't come
  back.

  This empty state is a trust artifact. It's the same move as your Methodology page's "0 flagged & hidden" — explicit honesty about limits, surfaced in the UI rather than buried.

  The PostHog event is the underrated bit

  Logging loose_results_shown lets you eventually answer:
  - What % of low-confidence searches do users actually opt into seeing? If it's < 20%, the empty state is doing its job — users are accepting "no match" and moving on.
  - Which queries trigger low-confidence most? That's your corpus expansion roadmap. The most-searched out-of-scope topics are the ones to add episodes about.

  Both of those are senior-PM-grade observations you'll have data for in two weeks. Worth mentioning on the Methodology page once you have the numbers.
